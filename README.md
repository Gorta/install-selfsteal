# selfsteal-installer

Скрипт для разворачивания ноды **VLESS Reality (self-steal) + Hysteria2** за **Caddy**, для панели [Remnawave](https://docs.rw/).

Нода отдаёт сертификат Let's Encrypt на сайте-заглушке и не требует отдельного ACME-клиента — Caddy получает и продлевает сертификат сам. Тот же сертификат автоматически пробрасывается в `remnanode` для Hysteria2.

## Что делает скрипт

- ставит Docker, если его ещё нет
- поднимает Caddy (получает сертификат Let's Encrypt на домен ноды)
- разворачивает `remnanode` со своим собственным `docker-compose.yml` (генерирует сам, на основе `NODE_PORT`/`SECRET_KEY` из вставленного вами конфига панели)
- **монтирует сертификат Caddy напрямую в `remnanode`**, чтобы Hysteria2-инбаунд мог его использовать
- **следит за обновлением сертификата** и сам рестартит `remnanode`, когда Caddy продлевает его по ACME (раз в ~60 дней)
- настраивает ufw (SSH с rate-limit через `ufw limit`, 80/443 tcp открыты, **443/udp для Hysteria2**, порт ноды для связи с панелью открыт только с её IP — или всем, если IP не указан)
- настраивает fail2ban на SSH (бан IP после 5 неудачных попыток за 10 минут)
- добавляет 2 ГБ swap, если его ещё нет
- включает BBR и базовые сетевые оптимизации
- случайно подбирает сайт-заглушку из внешнего репозитория (или использует встроенную, если скачать не вышло)
- **идемпотентен**: повторный запуск на уже настроенной ноде не ломает и не дублирует ничего — см. [Повторный запуск](#повторный-запуск-fresh--upgrade--refresh) ниже

### Как это работает

- Xray слушает `443/tcp` и обслуживает VLESS Reality, `443/udp` — Hysteria2
- весь TCP-трафик, который не прошёл Reality-аутентификацию (боты, зонды, случайные посетители), Xray переводит на `127.0.0.1:9443`
- на `127.0.0.1:9443` сидит Caddy и отдаёт сайт-заглушку — для стороннего наблюдателя порт 443 выглядит как обычный HTTPS-сайт
- Hysteria2, в отличие от Reality, — настоящий TLS поверх QUIC: клиент проверяет сертификат по `serverName`, поэтому ему нужен тот же валидный серт, что и decoy-сайту. Скрипт сам находит файлы сертификата в volume Caddy (`selfsteal_caddy_data`) и монтирует их в `remnanode` как `fullchain.pem`/`privkey.key` — путь одинаковый на всех нодах, так что один общий Config Profile в Remnawave работает без изменений

## Требования

- Ubuntu 24, root-доступ
- поднятая панель Remnawave на другом сервере
- уже созданная в Remnawave нода (Nodes → Create Node) — именно оттуда берётся `docker-compose.yml` (нужен только при первой установке)
- домен, A-запись которого указывает на IP сервера
- в Config Profile ноды добавлен Hysteria2-инбаунд, у которого `keyFile`/`certificateFile` указывают на `/var/lib/remnawave/configs/xray/ssl/fullchain.pem` и `.../privkey.key` — настраивается один раз в панели, скрипт этого не делает

## Использование

```
bash <(curl -fsSL https://raw.githubusercontent.com/Gorta/install-selfsteal/main/install-selfsteal.sh)
```

Скрипт сам определяет, что делать — на чистом сервере или на уже настроенной ноде — см. ниже.

### Первая установка

Скрипт спросит:

1. домен ноды
2. email для Let's Encrypt (можно пропустить на Enter)
3. IP панели (для правила ufw — панель должна иметь доступ к порту ноды; можно пропустить на Enter, тогда порт для получения конфигов и задач от панели будет открытым для всех)
4. содержимое `docker-compose.yml` ноды из панели — вставьте и нажмите `Ctrl+D`

В конце выводит диагностику: кто слушает порты 80/443(tcp)/443(udp)/9443, какой сертификат отдаёт порт с заглушкой, отвечает ли сайт-заглушка по внешнему пути, подключился ли сертификат к `remnanode`.

### Повторный запуск (fresh / upgrade / refresh)

Скрипт хранит состояние в `/opt/selfsteal/.install-state` (домен, email, IP панели, `NODE_PORT`, `SECRET_KEY`, версия скрипта на момент установки) и при каждом запуске сам решает, что делать — **без лишних вопросов**:

| Ситуация | Режим | Что происходит |
|---|---|---|
| Состояния нет (чистый сервер) | `fresh` | обычная интерактивная установка, как описано выше |
| Состояние есть, версия скрипта **изменилась** | `upgrade` | полный неинтерактивный пересбор: Caddyfile, оба `docker-compose.yml`, ufw, подключение сертификата — всё перегенерируется с сохранёнными ответами, вопросов не будет ни одного |
| Состояние есть, версия скрипта **та же** | `refresh` | ничего не перегенерируется, просто `docker compose pull && up -d` для Caddy и remnanode — подтянуть свежие образы |

### Watcher сертификата

После установки или апгрейда в системе появляется `cert-watch.timer` (systemd, проверка раз в сутки): он сравнивает хэш смонтированного в `remnanode` файла сертификата и, если Caddy его обновил по ACME, автоматически делает `docker restart remnanode` — Hysteria2 подхватывает новый сертификат без ручного вмешательства.

Проверить вручную:

```
/opt/remnanode/cert-watch.sh && systemctl status cert-watch.timer
```

## Сайты-заглушки

Шаблоны сайта-заглушки берутся из [Gorta/reality-stubs](https://github.com/Gorta/reality-stubs) — если недоступно, используется встроенная минимальная заглушка. Скачивается только при первой установке (`fresh`) — при `upgrade`/`refresh` существующий `/opt/html` не трогается.
